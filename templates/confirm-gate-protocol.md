# 确认门协议（Confirm-Gate Protocol）

每一层（L0→L1→L2→L3）推进前，必须走一遍确认门。**没有用户确认，不得进入下一层，不得臆造未确认的参数。**

## 固定节奏（每一轮都一样）

1. **提问**：Agent 针对当前层，提出 2~3 个具体候选 / 选项（不是一个开放问题）。
2. **生成**：经 MCP 让建模引擎产出候选几何（至少能看出形状差异）。
3. **回传证据**：把预览截图、关键尺寸、面数、水密状态回传给用户。没有证据不算完成。
4. **用户裁决**：用户选择 / 修改 / 要求再出候选 / 回退上一层。
5. **写回并锁定**：把裁决写进 `model-spec.md` 对应层，置为 `[LOCKED]`，同步 `params.json`，存一个工程检查点。
6. **推进**：只有该层 `[LOCKED]` 后，才进入下一层。

## 裁决类型与处理

| 用户裁决 | Agent 动作 |
|---|---|
| 选定候选 A | 写回 spec + lock + 检查点 + 进下一层 |
| 混合 / 修改 | 记录修改点，重出候选，回到步骤 2 |
| 都不满意 | 重新发散 2~3 个候选，回到步骤 1 |
| 回退上一层 | 把目标层从 `[LOCKED]` 改回 `[PENDING]`，作废其后所有层，回到目标层 |

## 硬规则

- **不越层**：上游层未 `[LOCKED]`，禁止询问或敲定下游层细节。
- **不臆造**：用户没确认的尺寸/形态，用占位符并标记 `[OPEN]`，不得填猜测值。
- **可追溯**：每次裁决写进决策日志，附用户原话或所选候选编号。
- **可回退**：推翻已锁层必须先回退，不能就地覆盖；检查点保留。
- **证据驱动**：预览/尺寸/校验结果来自 MCP 或脚本实测，不靠文字描述代替。

## 双引擎注意

- 引擎在 L0 元信息确定后即冻结；中途换引擎属于回退事件，需重新确认 L0 并迁移工程文件。
- Blender 用自定义属性存参数（它无原生参数化特征树）；FreeCAD 用参数对象 / 特征树。
