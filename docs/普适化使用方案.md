# 普适化使用方案

目标：同一套包在**任意工作区、重启 DSH 后、换一台机器**都能用。核心是分清「全局组件」和「每项目数据」，并消除硬编码路径。

## 一、组件分层（决定普适化策略）

| 层 | 组件 | 安装位置 | 作用域 |  needing 每项目重置 |
|---|---|---|---|---|
| 全局能力 | 5 个 skill | `~/.dsh/skills/`（或 DSH_HOME/skills） | 用户级，所有工作区 | 否 |
| 全局能力 | 2 个 MCP bundle | `~/.dsh/profiles/<profile>/node_modules/@local/` | profile 级 | 否 |
| 本机配置 | uvx/FreeCADCmd 绝对路径 | bundles 的 `cordis.patch.yml` | 每机器一次 | 换机器时 |
| 项目数据 | spec/params/工程/产物 | 当前工作区的任意目录 | 每项目 | 是（正常） |

**关键**：能力（skill/bundle）装一次全局生效；配置（绝对路径）按机器校准一次；数据（spec/产物）放当前工作区，彼此隔离。

## 二、安装（一次性）

### 前置依赖
- DSH（Desktop 或 Web profile）。
- Blender（ nominally ≥4.x，实测 5.3.0）。
- FreeCAD（可选，功能件必需；实测 27.1 Weekly，其它版本命令同为 `FreeCADCmd`）。
- Python 3.10+ 且 `pip install trimesh`（校验用）。
- uv / uvx（MCP stdio 启动器，`winget install astral-sh.uv` 或 `pip install uv`）。

### 步骤
1. **装 Blender MCP 插件**（若要实时通道）：
   ```
   uvx --python 3.11 mcp-for-blender install-addon
   ```
   （设置 `UV_PYTHON_PREFERENCE=only-managed DISABLE_TELEMETRY=true` 可避免用 conda python 并关遥测。）
2. **装 FreeCAD MCP addon**（若要实时通道）：把 `freecad-mcp` 的 addon 目录复制到 FreeCAD 的 `Mod` 目录（路径由 `FreeCAD.getUserAppDataDir()` 给出的 `Mod`），协议版本需与 uvx 包一致。
3. **克隆本包，填写本机路径**：`copy my-env.example.json my-env.json`，按本机改 `uvx` / `freecadcmd` / `dsh_home` / `dsh_profile`（my-env.json 已被 .gitignore 排除，不会入库）。
4. **体检**：
   ```
   powershell -ExecutionPolicy Bypass -File install\doctor.ps1
   ```
5. **渲染 bundle 模板**（把本机绝对路径替换进 `cordis.patch.yml`，产物在 `_rendered/`，已 gitignore）：
   ```
   powershell -ExecutionPolicy Bypass -File install\configure.ps1
   ```
6. **安装**：
   ```
   powershell -ExecutionPolicy Bypass -File install\install.ps1
   ```
   - skill：复制到 `~/.dsh/skills/<name>/SKILL.md`（旧文件备份为 .bak）。
   - bundle：**必须经 `dsh plugin --profile <p> add <渲染目录>` 注册**（pnpm 建 link 依赖 + Junction），单纯复制文件无效。请保持仓库目录不要再移动，否则 Junction 会失效。
7. **重启 DSH**（从托盘完全退出再开），验证 `mcp__blender__*` / `mcp__freecad__*` 工具出现。需要 MCP 实时时，去 Blender/FreeCAD GUI 点一次 Start Server；FreeCAD headless 路线无需 GUI。

## 三、日常使用（每次建模）

### 方式 A：对话驱动（推荐，DSH 内）
在**任意工作区**打开 DSH，直接说建模需求；`cad-spec-driver` 会在当前工作区建 `model-spec.md` 与 `params.json`，逐级确认。skill 是全局的，不依赖本包是否在该工作区——但建议把本包 clone 在某处，脚本引用其绝对路径，或把 `scripts/` 复制到项目内。

### 方式 B：命令行直接跑（不经 DSH）
脚本路径无关，可在任何目录运行：
```powershell
# 参数用环境变量 / CLI 传，产物默认落在 params.json 旁边的 output/
$env:CAD_PARAMS = "C:\任意路径\my-params.json"
$env:CAD_OUT    = "C:\任意路径\my-output"
& "<FreeCADCmd>" "<本包>\scripts\build_freecad_from_params.py"
python "<本包>\scripts\verify_stl.py" "$env:CAD_OUT\my-part-freecad.stl" 0.4
```
Blender 路线：
```powershell
& "<blender.exe>" --background --python "<本包>\scripts\build_from_params.py" -- "<params.json>" "<out_dir>"
```

## 四、跨工作区隔离

- 每个项目用自己的 `model-spec.md` / `params.json` / `output/`，命名前缀 `_spec` 字段区分。
- 不要在不同项目间共用 `output/`——证据文件按 stem 命名会覆盖。
- 若同一台机器多个 DSH profile，skill 装到对应 profile 的 skills 目录；bundle 用 plugin_manager 装到目标 profile。

## 五、换机器 / 重装

1. 克隆本包到新机器，复制并填写 `my-env.json`（本机 uvx/FreeCADCmd/DSH_HOME/profile）。
2. 顺序重跑 `doctor.ps1` → `configure.ps1` → `install.ps1`（install.ps1 会复制 skill 并经 `dsh plugin add` 重新注册 bundle）。
3. Blender addon / FreeCAD addon：按本机软件版本重装（插件装到**当前版本**的 addons/Mod 目录）。
4. Python：装 `trimesh`。
5. 完全重启 DSH；验证：`doctor.ps1` + DSH 里 `get_addon_status` / `get_rpc_status`。
6. 注意：若移动了仓库目录，旧的 Junction/link 会断，需在 profile 里 `dsh plugin --profile <p> remove @local/blender-mcp-bridge`（及 freecad）后重新 `install.ps1`。

## 六、常见坑（普适化相关）

- **硬编码路径**：早期脚本写死 `D:\Tim\...`，本包已改为相对脚本定位 + 环境变量；若你 fork 后新增脚本，务必沿用。
- **profile 不匹配**：bundle 装错 profile 会导致工具不出现；用 `plugin_manager list_bundles` 确认。
- **GUI server 未启动**：`Could not connect` / `get_rpc_status` 报错 → 去 GUI 点 Start Server，非 bundle 问题。
- **GBK 解码**：FreeCADCmd 把每个 CLI 参数当文件按 GBK 打开 → 参数一律走环境变量 `CAD_PARAMS`/`CAD_OUT`，读文件用 `utf-8-sig`。
- **`__main__` guard**：FreeCADCmd 用 exec 加载脚本，`__name__ != "__main__"` → runner 底部直接 `main()`。
